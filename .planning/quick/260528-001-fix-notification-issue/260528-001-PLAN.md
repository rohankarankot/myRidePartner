# Plan: fix the notification issue

## Goal
Ensure notifications (push and in-app) are properly generated and routed when:
1. A passenger requests to join a trip (sends a notification of type `JOIN_REQUEST` to the captain).
2. A request is approved or rejected (sends a notification of type `TRIP_UPDATE` to the passenger).
3. The captain or passenger taps the notification (correct routing to `/requests/[documentId]` for requests, and `/activity` for trip updates).

## Proposed Changes

### Backend
* [MODIFY] `backend/src/join-requests/join-requests.service.ts`
  - Inject `NotificationsService`.
  - In `create`: Call `notificationsService.create` to create a `JOIN_REQUEST` notification for the captain.
  - In `updateStatus`: Call `notificationsService.create` to create a `TRIP_UPDATE` notification for the passenger when request status is APPROVED or REJECTED.

### Mobile Client
* [MODIFY] `client/services/notifee-service.ts`
  - Modify `handlePress` to check `JOIN_REQUEST` type before checking `tripId`.
* [MODIFY] `client/app/notifications/index.tsx`
  - Modify `handleNotificationPress` to check `JOIN_REQUEST` type before checking `tripId`.
